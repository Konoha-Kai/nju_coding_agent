# 需求分析

## 1. 背景

考核题目要求个人独立设计并实现一个编程智能体。该智能体需要通过与大语言模型交互，自主读写文件、执行命令，并完成用户交给它的编程任务。项目应体现软件工程能力，而不仅是一次性 demo。

## 2. 用户角色

- 普通用户：输入自然语言编程任务，希望 agent 修改项目并给出结果。
- 开发者：维护 agent 工具、模型客户端、上下文和安全策略。
- 评委：通过代码、README、视频和面试判断系统是否真实可用、是否由学生理解并实现。

## 3. 功能性需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-01 | 支持从命令行输入任务 | P0 | 可通过 `python main.py "任务"` 启动 |
| FR-02 | 调用 DeepSeek Chat Completions API | P0 | API key 测试通过，能获得模型响应 |
| FR-03 | 支持读取目录和文件 | P0 | agent 能查看 workspace 内文件 |
| FR-04 | 支持写入或修改文件 | P0 | agent 能创建/修改指定文件 |
| FR-05 | 支持执行本地命令 | P0 | 能运行测试或脚本并获得 stdout/stderr/exit code |
| FR-06 | 支持工具调用循环 | P0 | 模型可多轮调用工具直到任务完成 |
| FR-07 | 支持错误反馈与重试 | P1 | 命令失败后 agent 可根据错误继续修复 |
| FR-08 | 支持执行日志 | P1 | 每轮模型请求、工具调用和结果写入日志 |
| FR-09 | 支持交互式确认危险操作 | P1 | 高风险命令执行前需要用户确认 |
| FR-10 | 支持上下文压缩或截断 | P2 | 历史过长时有明确处理策略 |

## 4. 非功能性需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-01 | 安全性 | 凭据不入库，文件和命令操作有边界 |
| NFR-02 | 可维护性 | 模块职责清晰，工具可扩展 |
| NFR-03 | 可测试性 | 工具、安全策略、解析器可单元测试 |
| NFR-04 | 可复现性 | README 提供环境和运行方式 |
| NFR-05 | 可解释性 | 面试时能解释主循环和设计决策 |

## 5. 约束

- 不使用现成 agent 产品封装界面。
- 不使用 agent 框架或 SDK。
- 不使用服务端托管代码执行或文件工具。
- API key 只能通过环境变量或未入库配置文件提供。
- 最终视频必须展示真实编程任务闭环。

## 6. 验收场景

最小验收任务：

```text
用户输入：请在 demo 项目里增加 add(a, b) 函数并补充测试。
期望行为：agent 查看项目文件，修改源码，新增或修改测试，运行 pytest，失败时修复，最终报告测试通过。
```
