# 项目开发规划

## 1. 项目定位

本项目目标是实现一个面向软件工程推免考核的简化 coding agent harness。系统通过 DeepSeek OpenAI 兼容 Chat Completions API 获取模型决策，由本地程序自行完成上下文管理、工具注册、工具调用解析、本地文件读写、命令执行、安全检查、日志记录和循环终止。

项目不使用 LangChain、LlamaIndex、OpenAI Agents SDK、Claude Agent SDK、AutoGen、CrewAI 等 agent 框架，也不依赖 Code Interpreter、Files API 等托管代码执行或文件工具。

## 2. 软件开发流程

采用轻量 Scrum / Sprint 方式推进，每个 sprint 都包含需求确认、设计、实现、测试、复盘和文档更新。

```text
需求分析 -> Backlog 拆分 -> Sprint 计划 -> 架构设计 -> 编码实现 -> 测试验证 -> 演示录制 -> 复盘改进
```

## 3. 交付物

- 可运行的 coding agent 项目代码。
- `README.md`：仓库开发说明。
- `README.txt`：最终提交用简短说明，1000 汉字以内。
- 2 分钟以内 mp4 演示视频。
- 开发文档：需求分析、Backlog、Sprint 计划、接口文档、架构图。
- Git 提交历史：体现真实开发过程。

## 4. 技术选型

- 语言：Python 3.12。
- 虚拟环境：conda `nju`。
- 模型接口：DeepSeek OpenAI 兼容 `/chat/completions`。
- SDK：仅使用 OpenAI Python 客户端作为 API 客户端库。
- 配置：`.env` + 环境变量。
- 文档图：Mermaid。

## 5. 参考依据

- DeepSeek API 文档说明其 API 兼容 OpenAI/Anthropic，OpenAI 兼容 base URL 为 `https://api.deepseek.com`。
- DeepSeek Chat Completions API 支持 `messages`、`tools`、`tool_choice`、`response_format` 等字段，工具类型当前为 function。
- DeepSeek Harness 文档强调 workspace、session、工具调用日志、权限审批和本地文件/命令能力。

## 6. 开发原则

- 先完成最小可运行闭环，再逐步增强安全和可维护性。
- 所有关键 agent 逻辑自行实现。
- 每个工具必须有清晰 schema、参数校验和错误返回。
- 所有本地文件操作必须限制在 workspace 内。
- 所有命令执行必须有超时和危险命令拦截。
- 每个 sprint 结束必须更新开发文档和 Git 提交。
