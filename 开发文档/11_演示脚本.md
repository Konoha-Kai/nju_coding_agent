# Sprint4 录屏演示脚本

## 演示目标

录屏控制在 2 分钟以内。重点不是把所有代码都讲完，而是让老师看到三件事：

- 这是一个自己实现的 Coding Agent Harness，不依赖 LangChain、AutoGen、OpenAI Agents SDK 等 agent 框架。
- Agent 可以真实调用 DeepSeek，支持交互式对话，自己维护上下文，自己选择并执行本地工具。
- 项目按软件工程方式交付，有需求、Backlog、Sprint、测试、benchmark 和交付检查。

## 2 分钟压缩版台词

如果录屏时间很紧，按下面顺序讲：

```text
这是一个基于 DeepSeek API 的 Coding Agent Harness。它不是套 LangChain 或 AutoGen，而是自己实现了模型请求、上下文管理、工具协议、本地工具执行、循环终止和错误处理。

项目按软件工程流程做了需求分析、Backlog、Sprint 计划、接口文档、架构图、测试和交付检查。现在我先跑全量测试，可以看到 84 个测试全部通过。

然后测试 DeepSeek API，返回 deepseek api ok，说明模型链路正常，API key 是从 .env 读取的，没有提交到仓库。

接下来运行交互式 agent demo。打开 --chat、--verbose 和 --compress-context 以后，可以看到我先问一句，Agent 回一句；我再追问运行测试，它会带着上一轮对话继续工作。上下文过长时，旧消息会被压缩成结构化 summary。过程中模型会决定调用 read_file 和 run_command，本地工具结果会回填到上下文，最后模型总结测试结果。

这个项目还保留了运行日志，方便复盘每次模型调用和工具执行。安全方面，文件访问被限制在 workspace 内，危险命令需要用户输入 yes 确认，命令参数里的路径穿越和 workspace 外绝对路径会被硬拦截。

最后能力测试使用公开 HumanEval 数据集，不是自己编 benchmark。完整 164 题中通过 159 题，pass@1 是 96.95%。SWE-bench 也调研过，但复现依赖 Docker 和较重环境，所以当前版本只记录复现困难。
```

## 录屏注意事项

- 不打开 `.env`。
- 不展示真实 API key。
- 不录太长的测试滚动过程，重点给最终 `passed`。
- 如果某次模型输出比较啰嗦，只讲工具调用和最终结果。
- 录屏文件控制在 2 分钟以内、200MB 以内。
- 最终提交压缩包只放 `README.txt` 和 `.mp4`。
